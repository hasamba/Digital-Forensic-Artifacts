# 098 - Settra ransomware, MeshAgent RMM, and BYOVD

Lab-safe companion to Huntress's [Ready, Settra, Go: New Settra Ransomware Variant Deploys MeshAgent RMM](https://www.huntress.com/blog/new-settra-ransomware-variant) (September 17, 2026). It reproduces the post-compromise artifacts of the two Huntress-investigated Settra incidents on a single disposable VM:

- **July incident** (consumer services / retail): MeshAgent RMM renamed to `mvtcs.exe`, C2 `45.13.122[.]7`; ransomware launched from `C:\Perflogs`; files renamed `.locked`; `RESTORE_FILES.txt` dropped; `cipher /w:D:\` free-space wipe and `ipconfig /flushdns` observed.
- **September incident** (manufacturing, Huntress agent installed mid-incident): MeshAgent RMM not renamed, C2 `193.5.65[.]114` (present in the certificate info and active connections); BYOVD `gdrv.sys`; ransomware launched from the user's Documents folder; files renamed `.locked_wip`; workstation `WIN-LIVFRVQFMKO` attribution artifact.

Both incidents share the domain-named `<victim-domain>_win64.exe` executable, the embedded child commands that clear Windows Event Logs, disable the Windows Recovery Environment (`reagentc /disable`), and remove a recovery partition (`diskpart`). The scenario preserves the exact September event-log clear list, **including the threat actor's misspelling** of `Microsoft-Windows-Defender/Operational` (correct: `Microsoft-Windows-Windows-Defender/Operational`) that left the Defender Operational log uncleared.

Run elevated with the standard lab gate via `.\SettraSim-Complete.ps1 -LabConfirmed`; artifacts remain under `%PUBLIC%\SettraSim`, and cleanup is separate (`.\Cleanup-SettraSim.ps1 -LabConfirmed`). Executable-looking artifacts are fixed-echo signed `cmd.exe` decoys. Two generated victim trees receive domain-named executables, notes, and `.locked`/`.locked_wip` sidecars while original canaries remain intact. No RMM is installed, no driver is loaded, no security tool is impaired, no event log is cleared, no recovery option is disabled, no recovery partition is removed, no free space is wiped, and no file is encrypted. Report IOC addresses are never contacted; only `127.0.0.1` is touched, with zero bytes. Real DCs are refused.

Observed behavior maps to T1133 (reported/unconfirmed VPN access), T1078, T1219 (MeshAgent RMM), T1543.003, T1068/T1211 via T1211-style BYOVD (T1211/T1562.001 with `gdrv.sys`), T1562.001, T1070.001 (clear event logs), T1490 (inhibit recovery: `reagentc`, `diskpart`), T1485/T1070.004 (`cipher /w` free-space wipe), T1486 (data encrypted for impact), and T1657-style extortion (`RESTORE_FILES.txt`).
